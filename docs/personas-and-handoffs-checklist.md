# Personas & Handoffs Checklist

Purpose: Ensure clarity in ownership, handoffs, and responsibilities across cross-functional teams.

How to use: Add this checklist to project README or One-pager. Fill in the owner names for each project.

- Project:
- Primary PM:
- Product Lead (PdM):
- Delivery Lead / Tech Lead:
- Scrum Master:
- UX Designer:
- Business Analyst:
- Support Lead:
- Release Engineer / CI Owner:
- Security Liaison:

Checklist
- [ ] All stories have a clear owner and acceptance criteria (owner: ______)
- [ ] UX assets attached to relevant stories and design handoff ticket created (owner: ______)
- [ ] BA has validated acceptance criteria with PdM and PM (owner: ______)
- [ ] Release Engineer has validated CI/CD and rollback plans for the release (owner: ______)
- [ ] Support Lead has runbooks and support contact info updated prior to release (owner: ______)
- [ ] Security Liaison has completed any required reviews or flagged blockers (owner: ______)
- [ ] Handoffs documented in project README or One-pager (link: ______)
- [ ] Onboarding note added: who to contact for each persona during incidents (owner: ______)
- [ ] Add a “Persona owners” section to release notes (owner: ______)

Acceptance criteria for adding new persona to docs
- [ ] Persona description is concise and includes 3–5 responsibilities
- [ ] Typical interactions and handoff points are listed
- [ ] At least one example of how this persona participates in a release or sprint cycle
- [ ] Stakeholders reviewed and agreed (if required)

Example: At kickoff, the PM assigns the Support Lead and Release Engineer; the UX Designer and BA confirm handoffs for upcoming sprint UI changes.
